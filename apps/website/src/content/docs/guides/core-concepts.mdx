## Context

Create a Volten context with `volten()`:

```ts
import { volten } from '@volten/core';

const v = await volten();
```

The context owns the WebGPU device and exposes the main execution helpers, including `v.pass()`, `v.run()`, `v.read()`, and `v.readDebug()`.

Alternatively, if you'd like to re-use an existing WebGPU device, you can pass the device as one of the initialization options:

```ts
const v = await volten({ device });
```

## Buffers and Uniforms

Buffers will internally hold WebGPU's Storage Buffers, if you're unfamiliar with WebGPU's types,
suffice to say Volten `Buffer`s are the go-to primitive to send large data into the GPU for
read / write access. In Volten, Buffers are also always an array of values.

`Uniform`s are normally used for small values shared with a kernel, usually for configuration.

```ts
import { Buffer, Uniform } from '@volten/core';

const data = new Buffer([1, 2, 3, 4], 'f32', 'rw');
const scale = new Uniform(2, 'f32');
```

## Kernels

Once you have defined the inputs and outputs of your kernel in terms of `Uniform`s
and `Buffer`s, you can use the `Kernel` class to define WGSL compute work.

```ts
import { Kernel } from '@volten/core';

const kernel = new Kernel(`
  fn main(gid: vec3u) {
    data[gid.x] = data[gid.x] * scale;
  }
`);
```

Volten will internally handle pipeline creation, bindings and layouts, shader generation,
buffer uploads, etc.
Volten also injects the compute entry point and workgroup size around your kernel function,
workgroup size is customizeable and will be explained in a future section of the docs.

## Passes

A pass connects a kernel with its resources, and creates a runnable `node` that can
be executed with `v.run`

```ts
const node = v.pass(kernel, { data, scale });
v.run(node);
```

After execution, use `read()` to copy data back to the CPU:

```ts
const result = await v.read(data);
```

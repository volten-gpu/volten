---
title: Nodes and Handles
description: Pass data from one node into another.
---

A node is the value returned by invoking a callable kernel or plan.

```ts
const A = copyValues({ input, output });
```

Every buffer-like binding on a node gets a handle with the same name.

```ts
A.input;
A.output;
```

You can use handles when one node consumes data from another node,
to make the dependency requirement clear:

```ts
const A = doubleKernel({ input, output: mid });
const B = offsetKernel({ input: A.output, output: result });
v.run(B);
```

Running `B` also runs `A`, because `B` depends on `A.output`.

This is Volten's graph model: handles connect nodes into a dependency graph, and `v.run(B)` runs the work needed to produce `B`.

## In-Place Chaining

Handles are created for in-place bindings too.

```ts
const A = updateInPlace({ data });
const B = updateInPlace({ data: A.data });
const C = updateInPlace({ data: B.data });
v.run(C);
```

This lets you chain work in a way that improves the readability of the dependency chain, as
well as letting you created more complex GPU compute execution dependency graphs

## Declared Outputs

Declared outputs matter when reading a node.

```ts
const computeResult = kernel({
    shader: `...`,
    outputs: ['result']
});
const node = computeResult({ input, result });
const output = await v.read(node);
```

If you choose to not declare outputs on your kernel, you can
alternatively read a specific buffer or handle:

```ts
const data = await v.read(node.data);
```

:::caution[Reserved names]
Public handle names cannot start with `_`, because Volten uses `_`-prefixed properties for internal node state.
:::
